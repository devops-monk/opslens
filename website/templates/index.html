How it works

From a requirement to an approved run

Four steps. Nothing before the last one can change anything.

  1. 1
    {{ icon('layout') }}

    Describe it

    Pick a template, build it step by step, or write a sentence. All three make the same small spec.

  2. 2
    {{ icon('eye') }}

    Review it

    Read it in plain English. opslens checks every table, column, parameter and safety rule as you go.

  3. 3
    {{ icon('flask') }}

    Test it

    See the rows it finds and the exact message or call each action would send. 0 changes made.

  4. 4
    {{ icon('shield') }}

    Approve it

    Deploy the exact spec you reviewed. Anything that changes things waits for your yes, and is logged.

About the AI planner {{ icon('arrow') }} 
$ opslens generate "every day, find running EC2 instances
    with no Owner tag, open a Jira ticket for each, and tag
    them after I approve" --dry-run

# ...then read what it drafted, in plain English:
$ opslens explain generated/ec2_tag_enforcement
- Finds running EC2 instances with no Owner tag, opens a
  Jira ticket for each, and flags them after approval.
- Runs every 24h (switched off until you deploy).
- Each run queries read-only for rows with: instance_id,
  arn, region, account_id (at most 50 rows).
- For each row, immediately: Open a ticket per instance
  (jira.create_issue, notify).
- Then it asks: "Flag these instances?" Only on approval,
  for each row: Tag the instance (aws.tag_resources).

Get started

Install it, or just try it

The live demo needs nothing. The installer needs one command and no sudo.

Installs Flowpipe, Steampipe and the five plugins (pinned, checksum-verified) and opslens itself, in your home directory.

curl -fsSL https://opslens.devops-monk.com/install.sh | sh

Prefer to read it first? curl -fsSLO https://opslens.devops-monk.com/install.sh, then OPSLENS_DRY_RUN=1 sh install.sh to see every command without running any. Add OPSLENS_EXTRAS="ai web" for the app and AI.

Python 3.11 or newer. Installs opslens only; add Flowpipe and Steampipe for live data.

pipx install "opslens[web,ai] @ https://github.com/devops-monk/opslens/archive/v{{ version }}.tar.gz"

Once on PyPI this becomes pipx install "opslens[web,ai]".

The image has opslens, Flowpipe, Steampipe and the plugins. Multi-arch (amd64, arm64), runs as non-root.

docker run --rm --network none abhaypratap/opslens search "unattached ebs volumes then open a jira ticket"
docker run --rm -p 8077:8077 abhaypratap/opslens serve --mode demo --host 0.0.0.0 --allow-host localhost
git clone https://github.com/devops-monk/opslens && cd opslens
python -m venv .venv && .venv/bin/pip install -e ".[dev]"
make test

Try it in two minutes

No cloud account, no credentials, no AI. Everything runs on built-in sample data.

opslens search "unattached ebs volumes, then open a jira ticket"
opslens pack install finops-cleanup/unattached-volumes
opslens explain  generated/unattached_volume_cleanup
opslens preview  generated/unattached_volume_cleanup --source demo
opslens serve                       # the web app on :8077

Then connect your accounts

opslens uses Steampipe's and Flowpipe's own credential setup, so it never stores your credentials. When opslens doctor is happy, test on live data, read-only, then deploy. How to connect Jira, Teams, Slack, GitLab, Opsgenie and AWS ›

Safety

A wrong guess cannot change your accounts

{{ icon('db') }}

Reads are guarded

One SELECT over catalogued tables, with a timeout and a row cap. Everything else is refused.

{{ icon('shield') }}

Changes wait

Deleting or modifying always sits behind an approval. Creating a ticket is additive and bounded.

{{ icon('check') }}

What you read is what runs

Deploys require the exact spec hash. Generated files are checked for hand edits.

{{ icon('lock') }}

Secrets stay put

Credentials live in Flowpipe and Steampipe. Specs with inline secrets are refused. No telemetry.
